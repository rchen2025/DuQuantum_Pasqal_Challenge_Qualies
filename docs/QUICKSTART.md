# qhack — CVRP clustering on a neutral-atom analog device (Pasqal challenge, Track A)

Cluster-first / route-second CVRP: the **capacity-feasible clustering** of customers onto identical
vehicles is encoded as a cost function on Pulser's `AnalogDevice` (80 atoms, 5 µm min spacing, 38 µm
radius, global detuning only), sampled on an emulator, decoded, and scored against §9.3
reference values (qubo-solver under a stated max solve time; tier S also brute-force-checked). Every model decision is derived step by step in **`docs/DERIVATIONS.md`** (single source of
truth; code follows it). Write-up: `docs/MODEL_WRITEUP.md`. Report: `report/report.pdf`.

## Reproduce the headline row (one command)

```bash
python -m pip install -r requirements.txt       # exact pins (Python 3.11+; the hackathon venv is 3.14)
python scripts/make.py demo                     # == validate instances, assert device limits, run S_seed00 with
                                                #    the random sampler and pulser-simulation (qutip), 500 shots,
                                                #    write out/demo/*.json and out/demo/results_demo.csv
```
(`make demo` is the same target for people with GNU make.) The demo runs
`python -m cvrp.run --instance instances/S_seed00.json --formulation onehot-ub --embedder polygons --backend qutip
--shots 500 --seed 0` — the headline row of `results.csv` (S_seed00, method `onehot-ub[emb=polygons]+qutip`) — using
the committed register in `embeddings/`; change `INSTANCE=`, `BACKEND=` (`qutip | emu-sv | emu-mps | numpy-sv | random`),
`SHOTS=`, `SEED=` on the command line. Emulator sampling is not seeded by Pulser's backends, so counts reproduce to
sampling noise (TV ≈ 0.05 at 500 shots); the register, pulse and all classical numbers reproduce exactly.

Other entry points: `python scripts/make.py test | deliverables | report` (pytest; D1–D5 pass/fail checklist;
figures + `report/report.pdf` with the page count checked ≤ 4). All commands and rules: `CLAUDE.md`.

## What is where
| | |
|---|---|
| `docs/DERIVATIONS.md` | every derivation (Eq. 1 → classical cost, the formulation, penalties, weights, embedding, pulse, judge Q&A) |
| `docs/MODEL_WRITEUP.md` | D2: formulations + §4 variable-count table (generated by `scripts/variable_count.py`) |
| `instances/` | D3: seeded instances with certificate, ρ, d_max/Q, best-known reference (brief §9.3: qubo-solver under a 60 s max solve time + constrained SA; tier S also brute-force-checked), solver settings (`python -m cvrp.validator instances/`) |
| `results.csv` | D4: one row per (instance, method, seed): §9 metrics, backend / bond dim / DMM / repair labels |
| `report/report.pdf` | D5: ≤ 4 pages, built from `docs/REPORT.md` |
| `docs/DID_NOT_WORK.md`, `docs/AI_USE.md` | honest failure log; what AI did per deliverable |
| `cvrp/` | the code (`common`, `instances`, `validator`, `exact`, `reference`, `model`, `formulations/`, `embed`, `pulse`, `metrics`, `run`, `results`, `baseline`, `report`) |
| `qopt/` | yesterday's generic toolkit, reused for the position optimiser and emulator adapters |

Reporting rules we hold ourselves to: every gap is on a **feasible decode**; repair is a separately labelled
method; we never report a mean cost; vehicles are identical so clusterings are compared as sets.
