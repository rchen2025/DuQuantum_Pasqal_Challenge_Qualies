# Model write-up (deliverable D2)

Capacity-feasible clustering of customers onto vehicles (Track A), cluster-first / route-second.
Every formula here is derived step by step in [`DERIVATIONS.md`](DERIVATIONS.md); this file is the
short deliverable that points at it. Numbers below are generated by scripts, never typed.

## Formulations (see DERIVATIONS.md §3–4)

| name (registry) | what | status |
|---|---|---|
| `assignment-only` | N·K one-hot variables, pairwise-distance objective, no constraints | table row only (DERIVATIONS §3.1) |
| `textbook` | one-hot + binary slack, squared penalties A (exactly-one) and B (capacity) | throwaway, plumbing only; not device-realisable (§3.3) |
| *ours* | to be registered at Gate 1 | DERIVATIONS §4 first, then `cvrp/formulations/<name>.py` |

Objective for both existing formulations: total pairwise Euclidean distance inside each cluster
(brief §5.1 "closeness"); additive over clusters, so the exact set-partition DP in `cvrp.exact` gives
proven references.

## Reference values

* Model gap reference: exact optimum of the constrained clustering model, by enumeration over
  K^(N−1) label-canonical assignments for tier S (`cvrp.model.model_optimum`) and by the set-partition DP
  for all tiers (`cvrp.exact`, additive objectives). Number of optimal clusterings is counted modulo
  vehicle relabeling (brief Pitfall 9.3).
* CVRP gap reference: exact TSP (Held–Karp, `cvrp.common.route_exactly`) on the best clustering of the
  constrained model, cross-checked with simulated annealing (`cvrp.reference`). Reference status
  (proven / best known) is recorded per instance.

## What we report

Per (instance, method, seed), brief Table 3: best model gap and CVRP gap on feasible shots only,
feasibility rate, P(gap ≤ ε) with ε stated, atom count, embedding fidelity (formula in DERIVATIONS §5),
reference status. Never a mean cost. Repair, when used, is a separate labeled method.
Soundness of every formulation's weights is certified by `cvrp.model.brute_force_check` on tier S
(DERIVATIONS §3.4 and §4) before any emulator run.
